# STAR 法则

「请讲一个你解决复杂问题的例子。」面对这个问题，很多人的回答会变成：先讲一堆背景，然后说「我们团队做了很多努力」，最后以「总之还不错」结尾。面试官听完，既不知道你具体做了什么，也不知道结果如何。

**STAR 法则**就是为了避免这种回答。它把一段经历拆成四部分，确保你讲的是**一件具体的事**，以及**你在其中的具体行动和可衡量的结果**：

*   **S — 情境（Situation）**：当时是什么背景？
*   **T — 任务（Task）**：你需要完成什么？难点在哪？
*   **A — 行动（Action）**：**你**具体做了什么？
*   **R — 结果（Result）**：带来了什么可衡量的变化？

STAR 来自行为面试（Behavioral Interview）的理论基础：**过去的行为是预测未来表现最好的依据**。面试官问的不是你的观点，而是你的行为证据。它同样适用于述职汇报、简历撰写和绩效评估。

!!! abstract "要点速览"

    - **四个要素**：情境、任务、行动、结果，缺一不可。
    - **时间分配大约 1:1:5:3**：行动是主体，情境和任务各一两句带过。
    - **用「我」而不是「我们」**：面试官要评估的是你，不是你的团队。
    - **结果必须量化**：「效率提升了」不如「处理时间从 3 天缩短到 8 小时」。
    - **提前准备 5~8 个故事**，覆盖不同能力维度，面试时按需调用。

## 四个要素详解

### S — 情境（Situation）：一到两句

交代**必要的背景**，让听者能理解后面的事。包括时间、角色、团队规模、业务背景等关键信息。

**只说必要的**。很多人在这里花了一半时间讲公司历史和组织架构，等讲到自己做了什么时，面试官的注意力已经散了。

> ✓ 「去年我在一家电商公司带 5 人的后端团队，负责订单系统。」

### T — 任务（Task）：一到两句

说清**你当时要达成什么目标，难点是什么**。任务要具体、有挑战，并且明确是**你的**责任。

> ✓ 「大促前两周，我们发现订单系统在压测中只能支撑预估峰值的 60%，我负责在大促前解决容量问题。」

**情境和任务的区别**：情境是客观环境，任务是你肩上的责任。

### A — 行动（Action）：回答的主体

这是最重要的部分，应该占到总时长的一半以上。要讲清楚：

*   **你具体做了哪几步**？按逻辑顺序讲，通常 3~4 步最清晰。
*   **你为什么这么选**？遇到岔路口时的判断依据，这最能体现你的思维方式。
*   **遇到阻力怎么处理**？说服了谁、权衡了什么。

> ✓ 「我做了三件事：第一，用压测数据定位到瓶颈在订单写入的数据库，而不是大家以为的网关；第二，评估了加机器、加缓存、分库三个方案，因为只剩两周，我选择了风险最低的读写分离加缓存；第三，和运维一起做了三轮演练，并准备了降级预案。」

**务必用「我」**。团队协作当然要提，但要说清楚你在其中的角色：「我推动了……」「我负责的部分是……」。通篇「我们」，面试官无法判断你的贡献。

### R — 结果（Result）：两到三句

用**数字**说明结果，并补上你的收获或后续影响。

> ✓ 「最终系统支撑住了实际峰值的 1.8 倍，大促期间零故障。这套读写分离的方案后来成了公司其他业务线的标准做法。回头看，如果能更早建立常态化压测，这个问题本可以提前两个月发现。」

**如果结果不理想怎么办？** 如实说明，然后讲你学到了什么、后来怎么改进的。面试官问「讲一次失败经历」时，考察的恰恰是你的反思能力——用一个假装成功的故事回答，反而是减分项。

## 好回答 vs 差回答

| | 差回答 | 好回答 |
| --- | --- | --- |
| 情境 | 「我们公司是行业头部，有五个事业部，我所在的部门……」（讲了两分钟） | 「去年我在一家电商公司带 5 人团队，负责订单系统。」 |
| 任务 | 「领导让我们提升系统性能。」 | 「大促前两周发现系统只能支撑预估峰值的 60%，我负责解决。」 |
| 行动 | 「我们团队加班加点，做了很多优化，大家配合得很好。」 | 「我做了三件事：定位瓶颈在数据库写入；在三个方案中选择风险最低的读写分离；和运维做三轮演练并准备降级预案。」 |
| 结果 | 「最后顺利支撑住了，领导很满意。」 | 「支撑住实际峰值的 1.8 倍，零故障；方案被推广到其他业务线。」 |

## STAR 准备模板

面试前准备 5~8 个故事，覆盖常见的能力维度。每个故事填一张表：

| 要素 | 内容 | 自检 |
| --- | --- | --- |
| 适用问题 | 这个故事能回答哪几类问题 | 一个故事常可覆盖 2~3 类 |
| S 情境 | 时间、角色、团队、背景 | 能在 20 秒内讲完吗？ |
| T 任务 | 目标 + 难点 + 我的责任 | 难点说清楚了吗？ |
| A 行动 | 步骤 1 / 2 / 3，以及关键取舍的理由 | 用的是「我」吗？体现判断力了吗？ |
| R 结果 | 量化结果 + 长期影响 + 我的反思 | 有数字吗？ |

**建议覆盖的能力维度**

| 维度 | 典型问题 |
| --- | --- |
| 解决复杂问题 | 讲一个你解决过的最难的问题 |
| 影响他人 / 跨部门协作 | 讲一次你说服了不同意见的人 |
| 面对失败 | 讲一次失败的经历 |
| 承受压力 / 应对变化 | 讲一次计划被打乱的经历 |
| 主动性 | 讲一件没人要求你做、但你主动推动的事 |
| 领导力 / 培养他人 | 讲一次你带人或辅导他人的经历 |

## 其他使用场景

**简历**：每条经历用「行动 + 结果」的压缩版 STAR 写。

> ✗ 「负责订单系统的性能优化工作。」
> ✓ 「主导订单系统容量改造，通过读写分离与缓存将承载能力提升 3 倍，支撑大促零故障。」

**述职 / 绩效面谈**：STAR 能让你的贡献具体可见，避免「今年很忙但说不清做了什么」。

**书面汇报**：如果是**提出建议**而不是讲述经历，应该用 [SCQA](../logical_thinking/SCQA-Framework-Tutorial-zh.md) 而不是 STAR。

## 常见误区

1.  **情境讲太长**。背景介绍占了一半时间，是最常见的问题。情境和任务加起来不要超过总时长的 1/4。
2.  **通篇用「我们」**。面试官无法从「我们做了很多努力」中评估你。要明确说出你个人的判断和动作。
3.  **行动没有层次**。「我做了很多优化」等于没说。拆成有逻辑顺序的 3~4 步。
4.  **结果没有数字**。「效果不错」「领导很满意」都不是结果。找出可量化的指标，哪怕是估算值。
5.  **只讲做了什么，不讲为什么这么选**。面试官真正想看的是你的判断力，而判断力体现在岔路口的选择上。
6.  **准备得太「完美」**。每个故事都是力挽狂澜的英雄叙事，反而不可信。承认取舍和遗憾更可信。
7.  **故事和岗位无关**。准备时就要按目标岗位的能力要求来挑选经历。

## STAR 与相关框架

| | STAR | STARL / STARR | [SCQA](../logical_thinking/SCQA-Framework-Tutorial-zh.md) | CAR |
| --- | --- | --- | --- | --- |
| 结构 | 情境-任务-行动-结果 | STAR + 学习/反思（Learning/Reflection） | 情境-冲突-疑问-答案 | 挑战-行动-结果 |
| 用途 | 讲述经历 | 讲述经历并体现反思 | 提出主张 | 简历中的压缩版 |
| 适合 | 行为面试、述职 | 讲失败经历、复盘 | 汇报、提案 | 简历条目 |

**关键区别**：STAR 回答「你做过什么」，SCQA 回答「我建议怎么做」。讲经历用 STAR，提方案用 SCQA。

## 常见问题

??? question "STAR 中每部分应该讲多长？"

    一个完整回答控制在 2~3 分钟。大致比例是情境 10%、任务 10%、行动 50%、结果 30%。行动是主体，情境和任务各一两句话带过即可。

??? question "被问到失败经历，也用 STAR 吗？"

    用，而且要在结果之后补充「我从中学到了什么、后来怎么改进的」（有时称为 STARL）。面试官考察的是反思和成长能力，所以不要用一个伪装成功的故事来回答。

??? question "没有特别亮眼的经历怎么办？"

    STAR 不要求故事惊天动地，要求讲清楚你的判断和行动。一次把混乱的交接流程理顺、一次主动补上缺失的文档，只要说清楚难点、你的选择和带来的变化，同样有说服力。

??? question "需要准备多少个 STAR 故事？"

    5~8 个通常够用。按能力维度准备，而不是按项目准备——一个项目常常可以从不同角度讲成两三个故事。

??? question "STAR 和 SCQA 容易混，怎么区分？"

    看目的：讲述一段**已经发生的经历**用 STAR；提出一个**面向未来的主张**用 SCQA。面试讲项目用 STAR，向老板申请预算用 SCQA。

## 延伸与关联

*   **[SCQA 框架](../logical_thinking/SCQA-Framework-Tutorial-zh.md)**：提出建议和方案时的表达结构，与 STAR 场景互补。
*   **[SBI 反馈模型](SBI-Feedback-Model-Tutorial-zh.md)**：同样强调「具体情境 + 具体行为 + 具体影响」，用于给他人反馈。
*   **[金字塔原理](../logical_thinking/Pyramid-Principle-Tutorial-zh.md)**：书面述职时，用结论先行的方式组织多个 STAR 故事。
*   **[复盘（AAR）](../meeting_effectiveness/After-Action-Review-Tutorial-zh.md)**：复盘产出的经验，正好是 STAR 故事的素材来源。
*   **[SMART 目标](../goal_management/SMART-Goals-Tutorial-zh.md)**：STAR 中的「结果」如果事先按 SMART 设定过，就天然是可量化的。
