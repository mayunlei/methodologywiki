# 价值主张画布（Value Proposition Canvas）

很多产品介绍都在讲「我们有什么功能」，而客户关心的是「这能帮我解决什么」。这两件事之间的落差，是大量产品卖不动的根本原因。**价值主张画布（Value Proposition Canvas）** 就是用来消除这个落差的工具：它把「客户到底要什么」和「我们到底提供什么」拆开，分别画清楚，再逐条检查是否对得上。

这个工具由亚历山大·奥斯特瓦德（Alexander Osterwalder）团队提出，是[商业模式画布](Business-Model-Canvas-Tutorial-zh.md)中「客户细分」和「价值主张」两个模块的放大镜。商业模式画布回答「整个生意怎么运转」，价值主张画布回答一个更前置、也更致命的问题：**这个产品真的有人要吗？**

画布分为两半：右边是**客户概况（Customer Profile）**，描述客户的真实状况，你只能观察和发现，不能发明；左边是**价值地图（Value Map）**，描述你的产品如何回应这些状况，这部分由你设计。两边对上了，就叫**契合（Fit）**。

!!! abstract "要点速览"

    - **右边（客户概况）**：客户任务（Jobs）、痛点（Pains）、收益（Gains）。描述事实，不是想象。
    - **左边（价值地图）**：产品与服务、痛点解决方案、收益创造方案。
    - **顺序很重要**：先画右边，再画左边。反过来做，你会不自觉地把客户需求往自己的产品上凑。
    - **不必全部匹配**：抓住最重要的几个痛点和收益即可，覆盖所有需求反而会让产品失焦。
    - **契合有三个层次**：纸面契合 → 市场契合 → 商业模式契合，后两者必须靠真实验证。

## 右半边：客户概况（Customer Profile）

**只填写你观察到和听到的，不填写你希望的。** 这部分的素材来自用户访谈、[民族志观察](../specialized_qualitative_methods/Ethnography-Tutorial-zh.md)、客服记录和行为数据。

### 1. 客户任务（Customer Jobs）

客户在他的工作和生活中**试图完成的事情**。分三类：

*   **功能性任务**：要完成的具体工作，比如「每月给 30 个客户开发票」。
*   **社会性任务**：希望在他人眼中呈现的形象，比如「在客户面前显得专业」。
*   **情感性任务**：希望获得的感受，比如「对账时不再提心吊胆」。

**关键**：描述客户的任务，而不是你的产品的用途。「使用我们的开票软件」不是客户任务，「准确且按时完成每月开票」才是。

### 2. 痛点（Pains）

完成任务过程中遇到的**障碍、风险和不好的结果**：

*   **不想要的结果**：花了三小时还对不平账。
*   **障碍**：数据分散在三个系统里。
*   **风险**：开错发票可能导致税务问题。

**痛点要量化严重程度**：是「极度困扰」还是「轻微不便」？这决定了客户愿不愿意为解决它付费。

### 3. 收益（Gains）

客户**期待、渴望或会惊喜的好结果**：

*   **必需收益**：没有就不能用的，比如发票符合税务规范。
*   **期望收益**：默认应该有的，比如操作不复杂。
*   **渴望收益**：有了会很满意的，比如能自动提醒逾期未付。
*   **意外收益**：客户自己都没想到的，比如自动生成现金流预测。

这四层的划分和 [KANO 模型](../user_research/Kano-Model-Tutorial-zh.md)高度呼应，可以配合使用。

## 左半边：价值地图（Value Map）

### 4. 产品与服务（Products & Services）

你提供的东西的清单：实体产品、数字产品、服务、体验。**仅仅是清单**，价值要在下面两项中体现。

### 5. 痛点解决方案（Pain Relievers）

你的产品**具体如何消除或缓解**右边列出的痛点。要一一对应：「自动从银行流水抓取数据」对应「数据分散在三个系统」这个痛点。

### 6. 收益创造方案（Gain Creators）

你的产品**具体如何创造**右边列出的收益。同样要一一对应。

## 填写步骤

1.  **先选一个客户细分**。不同客户的任务、痛点、收益完全不同，混在一张画布上必然失焦。
2.  **画右边，基于真实研究**。做 10~20 个用户访谈，问具体的过往经历（「上次开票花了多久？遇到什么问题？」），不要问假设性问题。
3.  **给右边排序**。把痛点和收益按重要程度从上到下排列。只有排在最上面的几条值得你花力气解决。
4.  **再画左边**。针对排名靠前的痛点和收益，设计解决方案。
5.  **连线检查契合度**。左边的每一项，对应右边的哪一条？**没有对应项的功能，就是候选的删减对象**；右边排名靠前却没有对应方案的，就是产品的缺口。
6.  **去验证**。纸面上的契合不算数，必须通过实验验证客户是否真的为此付费（见[精益创业](../product_development/Lean-Startup-Tutorial-zh.md)）。

**契合度自检**

- [ ] 右边的内容来自真实访谈，不是团队猜测
- [ ] 痛点和收益按重要度排过序
- [ ] 最重要的三个痛点都有对应的解决方案
- [ ] 左边没有「不对应任何客户需求」的功能
- [ ] 已设计实验来验证客户是否真的愿意付费

## 契合的三个层次

| 层次 | 含义 | 如何验证 |
| --- | --- | --- |
| **纸面契合**（Problem-Solution Fit） | 画布上左右两边对得上 | 团队讨论 + 用户访谈确认痛点真实存在 |
| **市场契合**（Product-Market Fit） | 市场用行为证明他们要这个 | 真实使用、留存、复购、付费 |
| **商业模式契合**（Business Model Fit） | 这门生意能赚钱且可持续 | 单位经济模型为正、可规模化获客 |

**很多团队停在第一层就开始大规模投入**，这是最常见的失败路径。纸面契合只是假设，市场契合才是事实。

## 应用案例

**案例一：面向小型会计事务所的开票工具**

*   **客户任务**：每月为几十个客户准确、按时开出发票并跟踪回款。
*   **痛点**（按重要度排序）：① 数据分散在客户的几个系统里，整理要几小时；② 逾期未付需要人工逐个核对和催收；③ 税务规则变化时容易出错。
*   **收益**：对账时间缩短；逾期率下降；审计时能快速提供凭证。
*   **痛点解决方案**：① 直接对接常见记账软件自动取数；② 自动识别逾期并生成催款邮件草稿；③ 税率规则随政策自动更新。
*   **收益创造方案**：一键导出符合审计要求的凭证包。
*   **检查结果**：团队原本还计划做「多维度经营报表」功能，但发现它不对应任何排名靠前的痛点或收益，于是推迟开发——这正是画布最大的价值：**帮你决定不做什么**。

**案例二：面向健身新手的 App**

*   **客户任务**：功能性是「保持规律锻炼」；社会性是「不想在健身房显得外行」；情感性是「不要因为做不到而感到挫败」。
*   **痛点**：不知道从哪里开始；担心动作做错受伤；坚持几天就放弃。
*   **收益**：看到自己的进步；锻炼不占太多时间。
*   **价值地图**：提供新手专属的 15 分钟计划（对应「时间少」和「不知从哪开始」）；每个动作配真人示范视频和常见错误提示（对应「怕做错」和「怕显得外行」）；连续记录与里程碑提醒（对应「坚持不下来」和「看到进步」）。
*   **注意**：这里的情感性任务和社会性任务往往比功能性任务更能决定用户是否留下，但也最容易被产品团队忽略。

**案例三：用画布发现错位**

某团队做了一款面向中小企业的「全功能数据分析平台」，强调「支持 50 多种图表、灵活自定义」。画完客户概况后发现，目标客户的首要任务其实是「每周一的例会上向老板汇报关键数字」，首要痛点是「不知道该看哪些指标」。「50 多种图表」不但不解决这个痛点，反而加重了「不知道看什么」的困扰。这个发现让团队把产品方向改为「预置行业指标模板 + 一键生成周报」。**产品能力没变，变的是价值主张。**

## 常见误区

1.  **先画左边**。先想好自己的产品优势，再去「找」客户痛点，必然会挑那些刚好能被自己解决的痛点。顺序必须是先右后左。
2.  **客户概况靠团队想象**。没有访谈支撑的画布，只是把团队的假设画得更好看了一点。
3.  **把产品功能写成客户任务**。「使用我们的 App 记录饮食」是功能，「控制体重」才是任务。
4.  **想覆盖所有痛点**。试图解决全部痛点的产品，往往每个都解决得不够好。抓住最严重的两三个。
5.  **一张画布装多个客户群**。必须每个细分客户一张，否则痛点和收益会互相矛盾。
6.  **纸面契合就当成功**。画布对上了只是假设成立，还需要真实的付费和留存来验证。

## 价值主张画布与相关工具的区别

| | 价值主张画布 | [商业模式画布](Business-Model-Canvas-Tutorial-zh.md) | [精益画布](Lean-Canvas-Tutorial-zh.md) | [同理心地图](../user_research/Empathy-Map-Tutorial-zh.md) |
| --- | --- | --- | --- | --- |
| 关注点 | 产品与客户需求是否匹配 | 整个商业模式如何运转 | 创业早期最高风险的假设 | 用户的内心世界 |
| 范围 | 两个模块的放大镜 | 九个模块的全景 | 九个模块，偏风险 | 单个用户类型 |
| 适合阶段 | 定义和打磨产品价值 | 描述和设计商业模式 | 高不确定性的早期创业 | 研究结论的整理阶段 |

常见的使用顺序：**同理心地图整理研究 → 价值主张画布打磨价值 → 精益画布或商业模式画布设计整体生意**。

## 常见问题

??? question "价值主张画布和商业模式画布是什么关系？"

    价值主张画布是商业模式画布中「价值主张」和「客户细分」两个模块的放大版。先用价值主张画布把这两块想透，再填进商业模式画布，整张图的质量会高很多。

??? question "右边的客户概况需要多少访谈支撑？"

    通常 10~20 个目标客户的深度访谈能让主要的任务、痛点和收益浮现出来。关键不是数量，而是问具体的过往经历，而非假设性问题。

??? question "痛点和收益是不是一体两面？"

    有重合但不等同。痛点消失不等于收益产生：发票不出错（消除痛点）和能预测现金流（创造收益）是两件事。分开列能让你看到更多机会。

??? question "B2B 产品怎么用这个画布？"

    B2B 中使用者、决策者和付款者常常不是同一个人，他们的任务和痛点也不同。建议为每个关键角色各画一张，再看价值主张如何同时回应他们。

??? question "画布填完之后下一步做什么？"

    设计实验验证最关键的假设：目标客户是否真的有这个痛点、是否愿意为你的解决方案付费。参见[精益创业](../product_development/Lean-Startup-Tutorial-zh.md)和 [MVP](../testing_and_validation/MVP-Tutorial-zh.md)。
