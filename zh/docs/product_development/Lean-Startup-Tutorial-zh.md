# 精益创业（Lean Startup）

创业失败最常见的原因，不是产品做得不够好，而是**做出了一个没人需要的好产品**。团队闭门开发一年，上线后才发现市场不买账，此时钱和时间都已经花完。**精益创业（Lean Startup）** 就是为了避免这种结局：它把创业看作一连串**需要被验证的假设**，而不是一份需要被执行的计划。

这套方法由埃里克·莱斯（Eric Ries）在 2011 年的同名著作中系统提出，思想源头有两个：丰田的[精益生产](../quality_and_operations/Lean-Operations-Tutorial-zh.md)（消除一切不创造价值的浪费），以及史蒂夫·布兰克（Steve Blank）的**客户开发（Customer Development）** 方法论（走出办公室去验证）。在精益创业里，最大的浪费就是**开发了没人用的功能**。

核心引擎是 **「开发—测量—认知」循环（Build-Measure-Learn）**，而且要**反过来规划、正过来执行**：先想清楚要学到什么（认知），再确定要测量什么指标，最后才决定开发什么最小的东西。

!!! abstract "要点速览"

    - **把创业当实验**：商业计划里的每一条，都是待验证的假设，不是既定事实。
    - **核心循环**：开发（最小的东西）→ 测量（真实用户行为）→ 认知（假设成立与否）→ 下一轮。
    - **规划时倒着来**：先定要学什么，再定测什么，最后定做什么。
    - **验证式学习**：以用户的真实行为为准，而不是问卷里的「我会用」。
    - **结果只有三种**：坚持（Persevere）、转型（Pivot）、放弃。要事先定好判断标准。

## 三个核心概念

### 1. 验证式学习（Validated Learning）

创业早期真正的产出不是代码，而是**关于「什么可行」的可靠认知**。衡量进度的标准不是「我们完成了多少功能」，而是「我们验证了多少假设」。

关键在于**用行为而不是意见来验证**。用户说「这个功能很有用」几乎没有信息量；用户为此付费、或者第二周又回来用了，才算验证。

### 2. 开发—测量—认知循环

| 环节 | 做什么 | 关键原则 |
| --- | --- | --- |
| **开发（Build）** | 做出能验证假设的最小东西 | 不是「功能最少的 1.0 版」，而是「能产生可靠认知的最小实验」，见 [MVP](../testing_and_validation/MVP-Tutorial-zh.md) |
| **测量（Measure）** | 收集真实用户行为数据 | 用可执行指标，不用虚荣指标 |
| **认知（Learn）** | 判断假设成立与否 | 事先定好成功标准，避免事后自我安慰 |

**循环速度比单次完美更重要**。一年转一圈的团队，远不如一个月转一圈的团队学得多。

### 3. 创新核算（Innovation Accounting）

传统财务指标（收入、利润）在创业早期几乎都是零，无法反映进展。创新核算的做法是：

1.  **建立基线**：用一个粗糙的 MVP 测出当前的真实数据（比如注册转化率 4%、次月留存 12%）。
2.  **调优引擎**：针对性改进，看指标是否向商业模型需要的方向移动。
3.  **决定坚持还是转型**：如果多轮努力后指标纹丝不动，说明基础假设有问题，该转型了。

**警惕虚荣指标**：累计注册用户数、累计下载量这类只会上涨的数字，看着漂亮但不能指导决策。应该看**同期群（cohort）指标**：这个月来的用户，有多少在第二个月还在用？

## 客户开发的四个步骤

客户开发由史蒂夫·布兰克提出，和精益创业是一体两面——精益创业管「怎么快速试」，客户开发管「去哪里试、试什么」。

| 阶段 | 目标 | 关键问题 |
| --- | --- | --- |
| **客户探索**（Customer Discovery） | 验证问题是否真实存在 | 这个问题真的存在吗？这些人真的是目标客户吗？ |
| **客户验证**（Customer Validation） | 验证解决方案和可重复的销售模式 | 他们愿意为此付费吗？能重复卖出去吗？ |
| **客户生成**（Customer Creation） | 规模化获取用户 | 如何把验证过的渠道放大？ |
| **公司构建**（Company Building） | 从探索型组织转为执行型组织 | 如何建立正式的部门和流程？ |

**前两步不能跳过**。大多数失败的创业，是在没完成客户验证的情况下，就开始烧钱做客户生成。

## 转型（Pivot）：什么时候该换方向

转型不是失败，而是**保留已验证的部分、改变未验证的部分**。常见的转型类型：

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| **放大转型** | 把原产品的某一个功能变成整个产品 | 一个项目管理工具发现用户只用其中的聊天功能 |
| **缩小转型** | 把整个产品缩成原来的一个功能 | 复杂的套件简化为单一工具 |
| **客户细分转型** | 产品对，但目标客户选错了 | 面向个人的工具转向面向企业团队 |
| **客户需求转型** | 客户对，但要解决的问题选错了 | 给同一群人解决另一个更痛的问题 |
| **平台转型** | 应用变平台，或平台变应用 | 从单一应用转为开放平台 |
| **商业模式转型** | 收费方式变化 | 从一次性买断转为订阅制 |
| **渠道转型** | 换一条触达客户的路径 | 从直销转为代理商分销 |
| **技术转型** | 用新技术实现同样的价值主张 | 换一套成本更低的技术栈 |

**判断信号**：MVP 的核心指标在多轮改进后仍然不动；用户访谈反复指向另一个问题；增长完全依赖持续投钱。

**建议**：固定一个「转型或坚持」的例会（比如每月一次），强制团队基于数据做出明确结论，避免在「再试一下」中无限消耗。

## 应用案例

**案例一：Dropbox 的演示视频**

创始人德鲁·休斯顿要验证的假设是「人们真的需要无缝的文件同步」。当时产品还没做完，做一个能用的版本需要数月。他拍了一段三分钟的演示视频，展示产品将如何工作，发在技术社区。等候名单在一夜之间从 5,000 人涨到 75,000 人——假设得到了强有力的验证，而成本只是一段视频。

**案例二：一个 B2B 工具的客户细分转型**

某团队做了一款面向自由职业者的发票工具，上线半年后月留存始终在 15% 左右，改了三版界面都没变化。客户访谈时发现，少数留存很好的用户都是**小型会计事务所**——他们每月要为几十个客户开票，痛点远比个人用户强烈。团队做了客户细分转型，把产品重新定位为面向小型事务所的批量开票工具，留存率提升到 60% 以上。**注意**：产品本身几乎没变，变的是目标客户。

**案例三：人工先行的「绿野仙踪」实验**

一个想做「AI 自动整理会议纪要」的团队，没有先训练模型，而是让用户上传录音，由团队成员人工听录音、手写纪要，在承诺的 2 小时内发回给用户。用户完全不知道背后是人工。两周跑了 40 份，验证了三件事：用户愿意上传录音、2 小时的时效可以接受、但用户真正在意的是「待办事项提取」而不是完整纪要。这个认知直接改变了后续的产品定义——而此时一行模型代码都还没写。

## 常见误区

1.  **把 MVP 理解成「粗糙的 1.0 版」**。MVP 是一次实验，目的是产生认知；不是功能删减版的正式产品。判断标准是「它能帮我们学到什么」，而不是「它少做了多少功能」。
2.  **验证了最容易的假设**。团队常常去验证「技术能不能实现」，而真正的风险往往是「有没有人要」。先验证最致命的那条。
3.  **用意见代替行为**。「您会用这个产品吗？」得到的答案普遍偏乐观。要看他们是否留下邮箱、是否预付、是否第二周回来。
4.  **没有事先定成功标准**。不定标准，任何结果都能被解读成「有一些积极信号」。
5.  **把精益创业当成「不做规划」**。恰恰相反，它要求把规划写成明确的、可证伪的假设。
6.  **转型太晚或太频繁**。太晚是不愿承认已验证失败；太频繁是没有给每个假设足够的验证时间。固定的决策例会能缓解两者。
7.  **大公司照搬**。成熟业务有已验证的商业模式，适用的是执行和优化；精益创业适用于高不确定性的新业务。

## 精益创业、设计思维与敏捷开发的区别

| | 精益创业 | [设计思维](Design-Thinking-Tutorial-zh.md) | [敏捷开发](Agile-Tutorial-zh.md) |
| --- | --- | --- | --- |
| 核心问题 | 这门生意成立吗？ | 我们解决的是对的问题吗？ | 怎么高效地把它做出来？ |
| 循环 | 开发—测量—认知 | 共情—定义—构思—原型—测试 | 计划—开发—评审—调整（迭代） |
| 主要产出 | 被验证（或被否定）的商业假设 | 被验证的问题与概念 | 可工作的产品增量 |
| 风险焦点 | 市场风险、商业模式风险 | 用户需求风险 | 交付与质量风险 |

三者并不冲突，实践中常串联使用：**设计思维找到对的问题 → 精益创业验证商业假设 → 敏捷开发高效交付**。

## 常见问题

??? question "精益创业和精益生产是什么关系？"

    精益创业借用了[精益生产](../quality_and_operations/Lean-Operations-Tutorial-zh.md)「消除浪费」的核心思想，但对「浪费」的定义不同：精益生产消除的是制造过程中的浪费；精益创业消除的是**开发没人需要的东西**这种浪费。

??? question "精益创业只适合初创公司吗？"

    不是。它适用于任何**高不确定性**的新业务：大公司的新产品线、内部创新项目、非营利组织的新服务。判断标准是不确定性高低，而不是公司规模。

??? question "什么是虚荣指标？"

    只会上涨、不能指导决策的累计类指标，比如累计注册数、累计下载量、页面浏览总量。与之相对的是可执行指标：同期群留存率、付费转化率、单位获客成本。

??? question "一个循环应该多快？"

    越快越好，但要保证认知可靠。早期的落地页或访谈实验可以几天一轮；涉及真实产品的实验通常一到四周。如果一个循环要几个月，先想办法把实验拆小。

??? question "怎么知道该转型还是该坚持？"

    看三点：核心指标在多轮针对性改进后是否移动；用户访谈是否反复指向另一个问题；增长是否完全依赖持续投钱。建议固定「转型或坚持」例会，用事先定好的标准来判断，而不是临时讨论。
